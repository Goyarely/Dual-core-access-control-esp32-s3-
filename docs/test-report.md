# 测试报告

> 所有数据来自 2026-10-30 ~ 11-03 的真实测试，硬件：ESP32-S3 N16R8 开发板 +
> GD32F303ZE 麒麟板 + ESP-01S Relay v4.0 继电器。每条都附现象与判定依据。

## 1. 协议库 link_proto（M7）

**方式**：`tools/test_proto.py`，39 项断言；其中 C 实现用 gcc 编译成宿主程序，
与 Python 实现对同一组输入比对（同源验证）。

| 测试 | 结果 |
|---|---|
| CRC16/MODBUS 标准校验值 `"123456789"` → 0x4B37 | ✅ |
| SipHash-2-4 官方向量（空串/1B/15B） | ✅ `0x726fdb47dd0e0e31` 等 3 项 |
| 编码→解码往返（6 种消息类型） | ✅ 字段原样还原 |
| **篡改检测**：type/seq/payload/CRC/MAC 各改 1 字节 | ✅ 全部拒绝（含"只改 CRC"由 MAC 抓住） |
| 粘包/半包/假帧头（噪声前缀 + 两帧连发 + 半帧） | ✅ 正确拆包、半包不误判 |
| 去重窗口（重复 seq、倒退、回绕） | ✅ C 与 Python 结果逐位一致 |
| C↔Python 交叉验证：CRC、MAC、整帧字节、去重 | ✅ `frame=AA550103070944332211EFBEADDE00B7CA379064D9` |
| 重放/新鲜度语义 | ✅ 时间戳 ±5s、nonce 查重 |

**串口模拟器**：loop:// 自环收发 2 帧 OK；后接真板验证见 §8。

## 8. GD32 执行侧（M9）

### 8.1 帧解析（M9a）

- 心跳解出、ACK 回传、ESP32 判定在线：✅
- 排雷记录：GPIOA 时钟未使能（printf 静默失败）、RS485 收发器抢占 PA3
  （每帧首字节 AA 丢失，PC5 拉高解决）、主循环每秒只读 1 字节（改一次取空）

### 8.2 继电器（M9b）

| 检查 | 结果 |
|---|---|
| 开锁请求 → 吸合 2s → 自动断开 | ✅ 听到两次"咔哒"，ESP32 收到 `result=0` |
| PC0 电平（ST-Link 读 GPIOC_OCTL） | ✅ `0x20`（吸合）↔ `0x21`（释放），周期 10s、脉宽 2s |

### 8.3 状态机（M9c-1，上电自测 + 实测）

| 用例 | 期望 | 实测 |
|---|---|---|
| 正常请求（时间戳/nonce 合法） | OK(0) | ✅ 0 |
| 同 nonce 重放 | REPLAY(2) | ✅ 2 |
| 时间戳偏差 30s | REPLAY(2) | ✅ 2 |
| 连续 5 次失败 | 第 5 次进锁定，后续 LOCKED(3) | ✅ 3，`fail=5` |
| 锁定期间刷脸/密码 | 一律拒绝 | ✅ `[fsm] 锁定中拒绝（剩 59s）` |

### 8.4 键盘（M9c-2a）

- 四角映射实测：`1`→R1=1、`5`→R2=2、`9`→R3=4、`*`→R4=1（即 R1C1/R2C2/R3C3/R4C1）✅
- PIN `1234` → `[fsm] 本地凭据通过 → 开锁 2000ms` ✅
- **默认关闭**（`KEYPAD_ENABLE 0`），密码已迁移到触摸屏

## 11. 遗留项与已知风险（如实记录）

| 项 | 现状 | 影响 |
|---|---|---|
| 照片攻击 | 活体已实现但**默认关闭** | 举照片可开门——当前版本明确接受此风险 |
| 管理员密码 | 编译期常量 | 改密码要重新编译 |
| MAC 密钥 | 源码硬编码、两板相同 | 量产需按设备独立注入 |
| 12V 电锁 | 未接（用继电器模块 + LED 验证） | 开锁瞬间的电源干扰整改未做，报告为 M13 遗留 |
| 端到端总时延 | 识别 ~0.4s + 链路 ~0.2s + 继电器机械动作 | 总体 < 1s，未做精确统计分布 |
| 触摸驱动 | 轮询模式 | CPU 占用比中断高（IO10 冲突下的取舍） |
