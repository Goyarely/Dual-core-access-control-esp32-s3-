# 排错手册

> 双核门禁开发全程的踩坑记录。格式：**现象 → 根因 → 解法**。
> 按领域分组；编号仅供引用。多数条目在对应源码注释里也有。

## A. 显示与字库

### A1. 中文一个像素都不画（字形表却能查到）

- **现象**：`lv_font_get_glyph_dsc()` 返回 ok=1、adv/box 正常，屏幕空白
- **根因**：`lv_font_conv` 默认输出**压缩位图**（bitmap_format=1），
  该工程 LVGL 9.6 下解码不生效
- **解法**：生成时加 `--no-compress --no-prefilter`（见 `tools/gen_fonts.sh`）

### A2. 整屏左右镜像（文字反向、色块顺序颠倒）

- **根因**：`esp_lvgl_port` 在 `add_disp` 时会用 `disp_cfg.rotation` 重新调
  `swap_xy/mirror`，**覆盖** `bsp_lcd_init` 里的设置——改后者等于白改
- **解法**：方向只在 `bsp_lvgl.c` 的 `rotation` 里配；本板 `mirror_x=true`

### A3. 字库白名单漏字（方块）

- **根因**：字符集是手工维护的白名单；且 16px/24px 曾是两份字符集，
  24px 漏成 20 个字，大字号全是方块
- **解法**：两份字库共用同一 CHARS；`tools/check_font.py` 在编译期扫描
  代码字符串字面量并与两份字库码点比对，缺字直接让 `idf.py build` 失败

### A4. 任意姓名显示方块

- **根因**：姓名是运行期数据，白名单子集不可能覆盖
- **解法**：短期把姓名用字加入 CHARS；长期方案是全量 GB2312 字库
  （约 1.5~2MB，16MB flash 装得下，未做）

## B. 摄像头

### B1. 画面花屏（屏和 SPI 都正常）

- **根因**：XCLK 给了 20MHz（OV2640 的常用值），**GC0308 硬性要求 24MHz**
- **解法**：`.xclk_freq_hz = 24000000`
- **教训**：先查时钟，再怀疑屏和接线

### B2. `Detected camera not supported`（踩过 3 次）

- **根因**：PWDN（PCA9557 IO2）不是低电平
- **验证**：I2C 扫得到 0x21 = PWDN 正确；扫不到 = PWDN 错
- **坑**：PCA9557 独立供电，**寄存器跨 ESP32 复位不丢**——设错一次后
  每次上电都错，必须断电重插

### B3. SCCB 能识别 0x21，但一帧都收不到

- **根因**：摄像头 FPC 排线虚接——I2C 两根线搭着，10 根数据线没通
- **解法**：断电重插排线、压紧锁扣
- **教训**：症状极像软件问题；"识别到但不出帧"先摸排线

### B4. 烧录后首次启动不出帧，复位一次恢复

- **根因**：ESP32 复位时摄像头不断电，XCLK 在半帧处断掉，传感器卡在残留状态
- **解法**：`bsp_camera_init()` 先给 PWDN 高→低脉冲（10ms/50ms），强制真上电

### B5. 识别相似度 0.69~0.72，同一个人刚录完就报陌生人

- **根因**：传感器横装、屏幕竖屏，**躺着的人脸**直接喂模型——
  检测还能找到，但关键点对不齐
- **解法**：把 90° 旋转提前到 RGB565→RGB888 转换；实测升到 0.83~0.89；
  顺带检测框坐标直接就是屏幕坐标，UI 侧反变换删除

## C. 触摸

### C1. "不灵敏"（点按偶发无响应）

- **根因**（三项叠加，都不是触摸芯片的问题）：
  1. `camera_task` 优先级 5 **高于** LVGL 任务的 4
  2. 每帧整图 240×320 走 SPI ≈123ms，期间 LVGL 处理不了触摸
  3. FT6336 扫描率默认 0x0E（约 10Hz）
- **解法**：优先级降到 3；预览隔帧刷新；POINTRATE 写 0x05

### C2. FT6336 坐标映射

- 竖屏下控制器报的就是屏幕像素坐标，只做边界夹紧
- 横屏（face_lvgl）则需要 swap+mirror——**换布局必须重新四角标定**
- **教训**：坐标反了绝不要在 UI 层"标签对调"来掩盖，要在
  `process_coordinates` 里修成屏幕像素

## D. 人脸库

### D1. 删除成员总是 ESP_FAIL

- **根因**：自建的 id 索引在清库/删除后与库内 id 错位
  （库内 id = num_feats_total+1，**只增不减、删除不重编号**）
- **解法**：直接解析 `face.db` 稀疏表
  （`[meta 6B][记录 id=1][记录 id=2]…`，删除 = 槽内 id 写 0），id 永远一致

### D2. 删空后重新录入，id 从 17 开始

- **根因**：同上，total 只增不减
- **解法**：删空（valid==0）时调 `clear_all_feats()`（实现就是 remove(face.db)）；
  界面显示改用"第几个成员"，删除时再查真实 id

### D3. 画面一抖就记一次失败，5 次锁门

- **根因**：识别库对"这一帧没人脸"和"陌生人"都返回 NOT_FOUND
- **解法**：三态区分（HIT/STRANGER/**NOFACE**），NOFACE 不计失败；
  且成功后必须先离开画面才允许重扫

### D4. 同一个人录了多个 id

- **根因**：录入前没有查重
- **解法**：录入前先识别一遍，相似度 ≥ 阈值就拒绝（提示"已录入过 x.xx"）

## E. 双板协议与链路

### E1. 偶发"链路无应答"（心跳明明是通的）

- **根因**：用 **seq** 给开锁请求去重。seq 是所有帧共用的计数器
  （心跳每秒 +1、ACK 也占号），而窗口只在开锁时更新——
  "上次开锁 seq=30、这次 seq=230"被判成倒退太远 → 静默丢弃且不回 ACK
- **解法**：删掉 seq 去重；重放保护由时间戳 + nonce 承担
- **教训**：去重窗口只对"同源连续流"有效，别用在低频消息上

### E2. 重传了但 GD32 没反应，日志也没有

- **根因**：载荷长度校验失败时整个 case 静默 break（不打印、不回 ACK）
- **解法**：任何拒绝路径都必须有日志/回执，"沉默丢弃"是联调大敌

## F. GD32 外设

### F1. printf 一个字节都没有（_write 却有调用）

- **根因**：`usart.c` 只使能了 USART0 时钟，没使能 **GPIOA**；
  模板里靠 `led_init()` 顺手使能，main 一旦不调 led_init，
  PA9 复用配置静默失败（引脚仍是浮空输入）
- **解法**：外设初始化**自己使能自己的 GPIO 时钟**，绝不依赖调用顺序

### F2. 每帧首字节 AA 丢失（16/17 字节）

- **根因**：PA2/PA3 与板载 **RS485 收发器 SSP485 并联**，其 RO 一直驱动 PA3，
  与 ESP32 的 TX 对顶；AA=10101010 跳变最多最先被打坏
- **解法**：PC5（RS485_RE/DE）拉高 → 接收器禁用、RO 高阻
- **教训**：**共用引脚的板载外设清单要看原理图**，不是看软件文档

### F3. frames_seen 恒为 0，但字节一直在涨

- **根因**：主循环沿用了示例的 `delay_1ms(1000)` 再读 1 字节——
  一帧 17 字节要攒 17 秒
- **解法**：一次把环形缓冲取空再解析

### F4. 中断里"顺手"再读一次 DATA 清 ORERR

- **后果**：多吞一个字节，每帧恰好少一个字节，极难排查
- **解法**：删掉；ORERR 只计数不读数

### F5. FWDGT 三个坑

1. **STPDET 实测不置位**（数据其实已收完）→ 等 BSY 清零代替
2. **一旦使能只有断电能关**——复位、重新烧录都不会关；
   超时必须给启动阶段留足余量
3. **别在 SysTick 里喂狗**（中断活着≠主循环活着）

### F6. 卡死测试没测到挂起

- **根因**：测试的 15 秒"预热"阶段没喂狗，还没走到挂起就被复位
- **解法**：健康状态也要喂；只有挂起后才停

### F7. ST-Link 读寄存器调试

- GD32 侧串口被占用/时序测试不便时，用
  `openocd … -c "mdw 0x4001100C"` 直接读 GPIO/外设寄存器验证
  （继电器脉宽就是靠读 GPIOC_OCTL 验证的：`0x20`↔`0x21`）

### F8. 读 GD32 调试串口会复位整板

- **根因**：CH340C 带 DTR/RTS 自动下载电路，pyserial 打开端口就拉复位
- **解法**：先开串口等 5 秒再测；或时序测试期间不抓日志，
  用 ST-Link 读寄存器替代

## G. 网络与后端

### G1. 表单嵌在 `<tr>` 里提交空数据

- **根因**：HTML 不允许 `<form>` 作为表格行的直接子元素，
  浏览器会把 form 移出表格 → 点保存提交的是空表单
- **解法**：表单放表格外，输入框用 `form="fN"` 属性关联；
  编辑页关闭自动刷新（否则刚输入就被刷掉）

### G2. 上报字段被截断（"passwor"）

- **根因**：`REASON_LEN 8` 装不下 `"password"`（8 字符 + '\0'）
- **解法**：12；**教训**：所有 strncpy 目标长度 = 最长合法值 + 1

### G3. ESP32 与 PC 不在同一网段

- **现象**：WiFi 已连接但 POST 不通
- **解法**：`ip -4 addr` 找到与设备同网段的网卡 IP，上报地址用它；
  ping 通 + 端口监听才能闭环

## H. 工程与工具链

### H1. 串口编号漂移

- 两个 CH34x（CH343/CH340）枚举顺序随插拔变化，`ttyUSB0/1` 会互换
- **解法**：按 `ID_MODEL_ID` 区分（7522=ESP32，7523=GD32）；
  优先用 `/dev/serial/by-id` 与 `ttyACM0`

### H2. 固件超出 app 分区

- 加 WiFi/HTTP 后 4.05MB > factory 4M
- **解法**：16MB flash 放大了 factory（6M）与 storage（2M）

### H3. IDF v6 没有 cJSON 组件

- **解法**：对自有服务端的固定格式，手写极简解析器（~30 行），
  不引入依赖；若需要完整 JSON，用组件管理器加 `espressif/cjson`

### H4. 字库检查曾经"漏检"

- **根因**：只扫了 16px；且把注释里的汉字也算进"用字"
- **解法**：两份字库都查；只扫字符串字面量（剥离注释）

## I. 方法论（跨领域的教训）

1. **先查时钟，再查接线**——花屏的最后答案往往是最简单的参数
2. **"识别到但不工作"先查物理层**——FPC 虚接、引脚共用的隐藏外设
3. **两层会翻的方向/字节序，只在一层修**——多层互相补偿必然踩坑
4. **静默丢弃是联调大敌**——所有拒绝路径必须有日志或回执
5. **时序测试别同时抓调试串口**（GD32 的串口一开就复位）
6. **上层不要补偿下层的错误**——下层修好了，上层的"补丁"就是新 bug
7. **每个会复位的路径都要能自我恢复**——EEPROM 恢复 + 默认锁定
8. **界面该多简单就多简单**——被否决的功能（每次转头、薄膜键盘）
   保留代码但默认关闭，成本沉没 ≠ 必须上桌
